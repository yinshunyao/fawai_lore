# 背景
1. 利用git作为本地文件多用户管理工具
2. 修改提交有版本概念
3. 不用merge功能

# 并发读写和语义一致性问题解决方案
## 问题描述
读写并发+语义一致性：一个智能体读了文件之后，思考修改写入，在写入之前，另外一个智能体来读取这个文件信息
- 怎么解决 后面智能体 读取信息可能 存在未来的偏差
- 浪费时间： 后面的智能体不能等待， 因为可能前面智能体不修改，或者修改了无关紧要的内容
- “信息滞后”或“知识割裂”：如果采用“读时固定快照 + 写时语义合并”方案， 很可能修改写入会包含关键信息， 后面智能体的工作丢失这些关键信息导致偏差很大
## 解决思路
1. 先入智能体 需要 快速决策，做变更备案，：简要描述内容


# 目标
1. 某个目录下管理1个Git仓库
2. 为每个用户 创建一个轻量分支
3. 所有用户都能任意查询所有版本文件
- 一般默认查询当前文件
- 需要感知文件是否修改中
3. 查询通过 git show <ref>:<file> 读取任意版本
